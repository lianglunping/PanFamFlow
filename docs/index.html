从零开始，按步骤跑通 PanFamFlow

本教程面向第一次接触 Linux、生物信息学工作流或 Snakemake 的使用者。你不需要理解每一行代码，但需要按顺序准备输入、修改一份 config.yaml、先校验再运行，并在出现错误时保留已经完成的结果。

开始第一步 先生成配置片段
中文为主 无需网页依赖 支持断点续跑 只改 config.yaml 目标家族，不做泛基因组组装

先用一句话理解这套流程

PanFamFlow 做什么？ 在多份已经组装和注释的基因组中，找出同一个目标基因家族的成员，然后比较其系统发育、HOG 占有率、Core/Soft-core/Shell/Cloud 类型、基因结构、复制、Ka/Ks、启动子和表达。
PanFamFlow 不做什么？ 它不从原始测序 reads 组装基因组，不构建 graph pangenome，也不把“注释中没找到”直接写成“这个基因已经丢失”。
输入审计
Canonical transcript
家族鉴定
家族树与 HOG
泛家族分类
进化与调控
整合报告

方法框架对应项目来源材料中的 HMMER/BLASTP 家族鉴定、IQ-TREE 系统树、Core/Soft-core/Shell/Cloud、复制与共线性、Ka/Ks、启动子和 RNA-seq；工程化实现进一步加入 canonical transcript、HOG、输入哈希、模块依赖与断点恢复。

0先判断：你的数据适合吗？

最低可运行

每个物种/材料至少有匹配的 genome FASTA 与 GFF3。

完成 Ka/Ks

还需要可靠的 CDS，且 CDS 与蛋白、GFF3 的 ID 能对应。

完成复制分类

需要合理外群；没有合适外群时，transposed duplication 必须降级解释。

完成表达分析

优先 FASTQ + 生物学重复；也可导入矩阵，但差异表达不能用 TPM 代替 raw counts。

常见误区多个样本的 BAM/VCF 即使材料不同，只要都比对到同一参考基因组，也不能直接当成多套独立 assembled genomes 做泛家族占有率。
  • 每套 genome 与 GFF3 来自同一 assembly/annotation 版本。
  • 物种或材料 ID 简短、唯一、以后不再随意更改。
  • 明确目标家族名称，以及 Pfam/InterPro/HMM 或参考蛋白证据。
  • 如果要比较群体，先定义 Wild、Cultivated 或其他分组，不能分析后再改。

1安装基础环境：mamba 管软件，uv 管 Python

建议在 Linux x86_64 服务器或 HPC 上运行。外部生物信息学软件由 Conda/Mamba 隔离；PanFamFlow 的 Python 依赖由 uv 按 uv.lock 锁定。

1.1 检查已有命令

mamba --version
uv --version
git --version

1.2 安装后创建 Snakemake engine

mamba env create -f environment.yaml
mamba run -n panfamflow-engine snakemake --version

1.3 安装 Python CLI

uv sync --locked --all-extras --dev
uv run panfamflow --version
uv run panfamflow list-modules
为什么不是把所有软件装进一个环境？HMMER、OrthoFinder、BUSCO、RNA-seq 和绘图依赖复杂。规则级 Conda 环境能减少版本冲突，并让失败任务可重现。

2下载代码并初始化分析项目

2.1 克隆独立仓库

git clone https://github.com/lianglunping/PanFamFlow.git
cd PanFamFlow

2.2 新建分析目录

uv run panfamflow init runs/my_family_project
cd runs/my_family_project

初始化后会得到：

my_family_project/
├── config.yaml
├── .panfamflow/config.schema.json
├── data/
├── references/
├── results/
├── work/
└── logs/
不要覆盖原始数据建议把原始文件放在只读位置，再用符号链接接入项目。不要为了“重新跑”而删除整个 results/、work/ 或 .snakemake/。

3.1 先做最简单的人工检查

head data/Os/genome.fa
head data/Os/annotation.gff3
grep -v '^#' data/Os/annotation.gff3 | head
sha256sum data/Os/genome.fa data/Os/annotation.gff3
检查项正确表现常见问题
FASTA第一条有效行以 > 开头下载到 HTML 错误页、压缩格式未识别
GFF3主体记录为 9 列，染色体名能在 FASTA 中找到GTF 冒充 GFF3、chr 名称不一致
IDgene/transcript/protein/CDS 可映射不同数据库版本混用
组装层级染色体级最适合定位和共线性scaffold 级结果被过度解释

4只修改一份 config.yaml

初学者最容易出错的地方不是命令，而是路径、缩进、物种 ID 和家族证据。YAML 使用空格缩进，不要混用 Tab。

4.1 最小可理解配置

schema_version: "1.0"

project:
  analysis_scope: target_pan_gene_family
  name: GPAT_pan_family
  root: .
  seed: 20260807
  results_dir: results
  work_dir: work
  logs_dir: logs

run:
  modules: [family, phylogeny, orthology, pan_family, report]
  cores: 32
  jobs: 32
  resume_mode: smart
  keep_going: true
  rerun_incomplete: true
  retries: 1

inputs:
  species:
    - id: Os
      name: Oryza_sativa
      genome: data/Os/genome.fa
      gff3: data/Os/annotation.gff3
      group: Cultivated
      representative: true
      outgroup: Og
    - id: Og
      name: Oryza_granulata
      genome: data/Og/genome.fa
      gff3: data/Og/annotation.gff3
      group: Wild
      representative: false
      outgroup: null

family:
  name: GPAT
  combine_evidence: intersection
  hmm:
    enabled: true
    hmm: references/family.hmm
    evalue: 1.0e-5
    domain_evalue: 1.0e-3
    cut_ga: false
  blast:
    enabled: true
    reference_proteins: references/family_reference.pep.fa
    evalue: 1.0e-5
    min_identity: 30.0
    min_query_coverage: 50.0

pan_family:
  core_min: 0.99
  soft_core_min: 0.90
  shell_min: 0.10
  rarefaction_iterations: 1000

4.2 四个必须理解的字段

analysis_scope

固定为 target_pan_gene_family，防止范围漂移到全基因组泛基因组。

species.id

形成稳定 ID 的前缀，建议只用字母、数字、点、短横线，不要中途更换。

combine_evidence

intersection 更严格，union 更敏感。正式阈值应由正负例校准。

hog_node

探索期可用 auto，正式分析要根据物种树节点冻结为具体 N*。

5真实项目先过“生物学启动门”

软件测试通过不等于生物学结论可靠。正式水稻 pilot 建议先冻结一个目标家族、5–10 套独立 assembled genomes、输入版本、SHA256 和人工正负例。

uv run panfamflow benchmark init benchmarks/rice_pilot
cd benchmarks/rice_pilot

# 先填写 benchmark.yaml、species.tsv 和 manual_review/manual_truth_set.tsv
uv run panfamflow benchmark audit \
  --manifest benchmark.yaml \
  --output audits/intake_001 \
  --allow-blocked

READY

没有阻断项和警告，可进入正式 pilot。

REVIEW

没有阻断项，但存在需要人工接受的降级项。

BLOCKED

至少一个 P0 条件未满足，不能把后续结果表述为已完成生物学验收。

审计输出包括中文 HTML、JSON、TSV、XLSX、输入文件清单和 SHA256 receipt。详细规则见 BIOLOGICAL_BENCHMARK.md。

6先校验、再看计划、最后 dry-run

6.1 配置与路径校验

uv run panfamflow validate -c config.yaml

6.2 查看依赖展开后的模块顺序

uv run panfamflow plan -c config.yaml

6.3 只构建 DAG，不真正计算

uv run panfamflow run -c config.yaml --dry-run
验收标准只有当 validate 无 ERROR、plan 的模块顺序符合预期、dry-run 没有 MissingInputException 时，才进入长时间计算。

7正式运行，或只跑你需要的部分

7.1 按 config.yaml 运行

uv run panfamflow run -c config.yaml

7.2 临时只运行家族鉴定与系统树

uv run panfamflow run -c config.yaml \
  -m family \
  -m phylogeny

7.3 只运行泛家族分类

uv run panfamflow run -c config.yaml -m pan_family

依赖会自动补齐。例如选择 pan_family 时，会自动包含 qc → normalize → family 和 orthology，但不会无故触发表达或启动子模块。

8报错后不要从头来：修复后断点续跑

默认 resume_mode: smart。Snakemake 会跳过完整且仍有效的任务，只重跑失败、不完整、缺失、输入变化、参数变化、代码变化或软件环境变化的任务。

8.1 查看状态和日志

uv run panfamflow status -c config.yaml
find logs -type f -maxdepth 3 | sort
# 查看某个失败日志末尾
 tail -n 80 logs/<module>/<job>.log

8.2 修复原因后继续

# 推荐：仍然执行原命令
uv run panfamflow run -c config.yaml

# 或显式恢复
uv run panfamflow resume -c config.yaml

# 只恢复表达模块及依赖
uv run panfamflow retry -c config.yaml -m expression
只有确认没有其他 Snakemake 进程时才解锁如果异常退出留下 stale lock，可先确认没有正在运行的作业，再执行 uv run panfamflow run -c config.yaml --unlock。
禁止伪造完成不要手工 touch 结果或 .done 文件，不要随意删除 .snakemake/。这些操作会破坏 provenance 与自动跳过。

完整恢复策略见 RESUME.md。

推荐阅读顺序

  1. 先看 QC 与输入哈希：确认使用的文件版本、物种数和 ID 映射。
  2. 再看家族成员表：查看 HMM/BLAST/domain 证据、拒绝原因和异常长度。
  3. 再看树与 HOG：检查支持率、HOG 节点和未分配成员。
  4. 最后看泛家族、复制、Ka/Ks、启动子和表达：结论必须能回到具体 gene/HOG。
  5. 综合结果：以 master_gene_table.tsv/.xlsx 为主，不要只依赖单张图。
图表不是结果的唯一载体所有图都应能追溯到 TSV/XLSX、配置参数、软件版本、随机种子和输入 SHA256。

10四条生物学解释红线

树上 clade ≠ 自动成为 HOG

亚家族、树分支、OrthoFinder HOG 和材料间 pan-locus 是不同概念，不能用一个编号代替全部。

注释缺失 ≠ 已验证 gene loss

还可能是 assembly gap、annotation miss、fragment 或 ID 映射失败。重点缺失要做基因组回搜与共线性验证。

pairwise Ka/Ks > 1 ≠ 已证明正选择

它只是候选信号。重点基因需追加 branch/site model、LRT 和多重检验。

motif/TPM 差异 ≠ 已证明调控机制

motif 是序列匹配，TPM 主要用于描述。功能机制还需 TF、表达方向、结合或实验支持。

Core/Soft-core/Shell/Cloud 阈值

默认阈值是可执行口径，不是普适自然定律。正式分析应记录阈值并做敏感性分析；低质量材料和 UNCERTAIN 状态不能简单进入“缺失”分母。

11最终验收与归档

  • 输入 genome/GFF3/protein/CDS 版本和 SHA256 已冻结。
  • canonical transcript 规则统一，gene/transcript ID 映射闭合。
  • 家族正例、负例、拒绝候选和 fragment 都有审计记录。
  • 家族树保存原始 MSA、trimmed MSA、模型和支持率。
  • OrthoFinder 使用明确 HOG node，并检查 unassigned family members。
  • 泛家族分类阈值、分母和随机种子写入配置。
  • DupGen 外群和唯一分类优先级明确。
  • Ka/Ks pair 来源、无效 pair、Ks=0 和 saturation 均有统计。
  • 启动子坐标、截断、上游基因重叠和 motif 数据库版本可追溯。
  • 表达分析保存样本设计、文库方向、生物学重复、batch 和 contrast。
  • 结构化结果同时输出 TSV/XLSX，正式图同时输出 PDF/高分辨率 PNG。
  • 重新执行相同命令时，已完成且有效的任务自动跳过。

常见报错与最小修复动作

Configuration error / YAML 解析失败

常见原因是缩进、Tab、字段拼写或类型错误。先运行：

uv run panfamflow validate -c config.yaml

不要跳过校验直接运行。

MissingInputException

说明 DAG 需要的输入文件不存在或路径不对。检查相对路径是相对于项目根目录，而不是当前随意所在的目录。

Conda 环境求解失败

先确认 channel 顺序和 mamba 版本，再删除对应的失败规则环境缓存，而不是删除全部结果。保留日志与失败环境信息以便复现。

OrthoFinder 没有目标成员或 HOG 节点不对

先检查 stable ID 是否进入 canonical proteome，再查看 SpeciesTree_rooted_node_labels.txt，最后审计 unassigned_family_members.tsv。不要把未分配直接解释为缺失。

IQ-TREE 中断

保留相同签名工作目录和 .ckp.gz，用相同输入、prefix 和参数恢复；不要默认加 -redo。

LockException

先确认没有其他 Snakemake/PanFamFlow 进程。仅当锁来自异常退出时：

uv run panfamflow run -c config.yaml --unlock
uv run panfamflow resume -c config.yaml
第二次运行仍把所有任务重跑

检查是否改变了输入 mtime、分析参数、代码或 Conda 环境；检查输出是否通过原子写入和完成校验；不要把 CPU/内存等执行参数误放进分析签名。
